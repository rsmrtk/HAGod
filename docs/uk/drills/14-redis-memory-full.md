# Drill 14: У Redis закінчилась пам'ять

**Мета.** Побачити, що насправді роблять noeviction і allkeys-lru і чого кожен коштує.

## Історія
Batch-завдання завантажує дані, і Redis починає відхиляти записи. Або гірше: тихо видаляє дані, які були потрібні.

## Спершу передбачте (запишіть)
- Яку помилку отримають клієнти?
- Що зникне після зміни політики?

## Запуск
```sh
make drill-14
make verify-14      # змінює політику, потім перезавантажує тренувальні ключі
```

Тримайте `make watch` відкритим у другому терміналі.

## Спостерігайте: команди, які варто спробувати самому
```
INFO memory
CONFIG GET maxmemory-policy
INFO stats          # evicted_keys
redis-cli --bigkeys
MEMORY USAGE bigkey:audit_blob
DBSIZE
```

## Що ви маєте побачити
З `noeviction` записи падають: `OOM command not allowed when used memory > 'maxmemory'`, а читання працюють. Після `allkeys-lru` записи знову проходять, але **тисячі наявних ключів витісняються** (`evicted_keys` росте): у лабораторії багато тренувальних ключів зникають, і `make seed-redis` їх відновлює.

## Зрозумійте
`noeviction` захищає дані й зупиняє записи; `allkeys-lru` продовжує писати й **тихо видаляє найдавніше використані ключі, зокрема ті, що були потрібні**. Політики `volatile-*` видаляють лише ключі з TTL: безпечно для суміші кешу й постійних даних, але тоді кожен кеш-ключ має мати TTL (подивіться на `cache:rates:*`, який його не має).

Також `CONFIG SET` втрачається при рестарті, якщо не зробити `CONFIG REWRITE`, а після failover новий master має **власну** конфігурацію.

## Виправлення
Використовуйте правильну політику для навантаження, ставте TTL на кеш-ключі, знаходьте великі ключі, розраховуйте `maxmemory` на дані плюс буфери реплікації, а дані на кшталт черг тримайте в окремому Redis.

## Ваш runbook
Напишіть три рядки, перш ніж читати відповіді: **симптом → як підтвердити → що робити.** (Шаблон: `docs/07-runbook-template.md`.)

## Питання
1. Яка політика для (а) кешу сесій (б) черги платежів (в) rate limiter?
2. Що відбувається з лімітом після failover?
3. Чому пам'ять для реплікації теж враховується?

---

### Відповіді (читайте після спроби)
1. (а) `allkeys-lru` або `volatile-lru` з TTL; (б) `noeviction` на власному інстансі; (в) `volatile-ttl` або `allkeys-lru` (лічильники однаково спливають).
2. Новий master використовує **власний** конфіг; якщо ви змінили його лише через `CONFIG SET` на старому master, змін нема. Занесіть у `redis.conf` на кожному вузлі (і `CONFIG REWRITE`).
3. Вихідні буфери реплік і replication backlog живуть у пам'яті master; повільна репліка може змусити їх рости (`client-output-buffer-limit replica`).
